## Groups 1-3 - inventory, offsets and schema

Existing `media/baseset/openttd/map_layers.png/.nfo`, 66 live Action5 type-0x1C entries and quantizer CONTRACT_RANGES remain unchanged. The public constants and packing list agree on offsets **0..65**. The optional Deep elevator housing range **66..73** is commented/unactivated, so this draft protects it explicitly instead of occupying it. Native terrain/survey/control/area overlays have a documented future append range **74..167** (94 sprites), with activation false; later packing must extend loader/baseset bounds atomically. Current `MAP_LAYER_SPRITE_COUNT` and `SPR_NEWGRFS_BASE` are unchanged. Vehicle/building/cargo art uses MLVI package-local logical IDs; an asset ID is not a runtime or packed sprite offset.

[Manifest](../../../../../../../../../OpenTTD3/docs/zz-reach2/upgrades/2026-10/assets/multilayer_sprite_manifest.json) schema version 1 has 141 independent families and **58,059 exact required source sprites**, counting direction x state x frame x front/back part x footprint tile variant. Multi-tile layouts have distinct per-cell art requirements; these sprites do not each consume an industry tile-definition slot. A feature may select per-cell graphics through at most four logical tile kinds as budgeted, with callback/layout mapping reviewed during packing. Each record includes the six public fields plus kind, state list, native size/bounds, footprint, tile variants, palette/transparency/company/animation rules, front/back parts and output namespace/hash.

All new source rows explicitly have `status=planned`, `path=null` and no output hash; no nonexistent final file is presented as delivered. The existing native reference sheet has an actual SHA256 in the manifest. Source authoring must supply immutable provenance/rights and hashes before packing. Uniqueness, complete engine views, state/size bounds and missing/fictitious source cases are enforced by [the producer fixture](../../../../../../../../src/tests/fixtures/cleanup/source-epochs/openttd3-75ea75718f/009c356f0db53619-multilayer_sprite_contract.py). A vehicle example is `vehicle.model-00`; a multi-tile building example is `mine.CORE` (3x3, four engine door views, back/front pairs, four states/four frames). Invalid sources stop later authoring/packing acceptance.

## Groups 4-5 - style, readability and palette

Authored normal-zoom assets use the TTD isometric scale: **64x31** ground diamond with anchor `(-31,0)`, per-tile buildings **64x64** at `(-31,-33)`, initial specialist vehicle canvas **64x48** at `(-32,-32)`, toolbar/purchase icons **20x20** at `(0,0)`. A building footprint is world tiles, not a canvas crop; crop shifts must preserve the common world anchor and front/back alignment. One top-left light direction, grounded contact/shadows, restrained depth palettes and different resource shapes retain readability at native size. Engine scaling supplies other zooms; optional 32bpp/high-zoom sources are later work.

Five tube silhouettes must be distinct before color: Mole has a low ribbed hopper/cutter-free blunt nose; Crate a latched rectangular box; Cistern rounded end caps/tank body; Shield a thick drum-protection casing; Forge a long flatbed/gantry with oversized load. Empty/partial/full poses alter visible cargo/hold geometry, service/blocked poses use a readable status marker outside cargo silhouettes, and working frames maintain identical anchor and bounds. Underground cool grey versus Deep basalt accents remain distinct in monochrome shapes; URAN uses sealed-drum identity rather than a generic ore recolor.

First deliverable is DOS 8bpp with index-0 transparency. Only explicit company-color masks may use reserved company colors; automatic quantization must avoid those and reserved animation ranges, following the existing quantizer policy. Animation is authored frames, not accidental palette cycling. No ETI imagery or copied third-party source is reused. The existing native sheet and prior generated raw assets are repository references for scale/anchors; retain their original provenance and licensing records before redistribution. New families are first-party originals under the project's asset policy; source rights are not inferred from an unrelated code license. This handoff does not declare undelivered art licensed or accepted.

These placement templates expose alignment/size contracts for later state art. Template labels/colors are geometry aids, not final art. Exact swept-consist collisions, per-frame state readability and operational occlusion must still be validated in consumers; no live runtime result or human final-art acceptance is claimed.
