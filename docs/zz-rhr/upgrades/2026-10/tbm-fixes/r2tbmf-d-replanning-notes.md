## Current scope and discovered producers

- `PlanTBMCommission` already selects one eligible retired, empty cutter withdrawn at the same original portal through `IsTBMConsistReusableAtPortal`, `LayerPortalCommissionRequest::reuse_cutter` and the acquisition owner. Preserve that path; do not implement a duplicate reuse/purchase transaction. It does not extend an active project or enable alternate hangars.
- `ReserveExcavationJob` is in **`src/excavation.cpp`**, not `excavation_jobs.cpp`. The latter owns structural/save reconstruction validation. Fresh reservation correctly refuses copied progress and all existing claims.
- `PlanExcavationRoute` and `QuoteExcavationCells` reject every active claim. Simply invoking the existing preview for a live TBM therefore cannot extend its accepted work.
- `PrepareExcavationPass` recomputes a fresh pass from current terrain and calls the fresh-cell quote. It must not replace old boundaries on a loaded/partially worked project: old Earth/Rock cargo and unfinished work need their accepted exchange points retained.
- `TBMProject` owns the actual machine, model, immutable parts, phase, heading, exchange/origin and fractional work. `ExcavationJob` solely owns complete accepted geometry, cursor, partial work, receipts and saved pass terms. Extension must retain both IDs and all those existing quantities.

## Design for the remaining implementation

Active-project extension appends **after the full accepted route**, including its not-yet-dug portion. It does not replace existing cuts or reinterpret the current physical head as the future route endpoint. The UI/command should require an eligible paused unfinished project so confirmation can revalidate the exact job revision. Completed/cancelled history is not silently reopened; the existing retired-source reuse path remains the separate next-project operation, with broader parking/reassignment developed in Groups7-8.

Reconstruct the full head/trailing history from the actual measured consist and replay every existing accepted advancing sweep. A new plan can regard those old sweeps as virtual future floor, but no live terrain or claim changes during preview. Other jobs' claims, foreign infrastructure, non-plain rail buildings, missing authorization and immutable model/layer restrictions still refuse.

Atomic append belongs in the geology owner:

1. Revalidate exact existing identity/revision/actor, unfinished state and immutable completed/current prefix. Merge only new requested/authorized geometry and append canonical cuts.
2. Preserve old cursor, partial work, paid/output statistics, source anchor and all existing pass/exchange boundaries. Keep the previous final return as a mandatory empty-wagon exchange before the extension.
3. Quote only new extension cells after treating the old full route as already opened in the forecast. Do not call a fresh full-pass estimator against its own active claims or double-charge old work.
4. Validate newly appended support/backing, per-cut independent capacities, physical turn layout and aggregate saved-geometry/claim bounds. Compute additional future pass boundaries and refresh the existing static fingerprint.
5. Allocate replacement geometry/maps first, then atomically add only new same-job claims and set newly accepted Solid cells to Excavating. No cash/cargo transfer, vehicle purchase, progress reset, saved-ID allocation or direct rock opening occurs. Future actual cutting retains its existing charge/spoil owner.
6. The TBM owner increments its own revision only after all preflight succeeds. No new private route/progress or vehicle registry is needed. Existing variable-length geometry/pass save fields can represent an append, but actual mid-work file reload and stale quote tests remain required.

UI work still required: explicit new project versus existing-machine extension; straight tunnel versus area intent; visible canonical path/turn/outline and time/spoil preview; exact refusal and revision-bound confirmation. New area must not silently buy a second cutter for an active project. Surface/Underground/Deep portal model/origin resolution and measured consist capacities remain authoritative.
