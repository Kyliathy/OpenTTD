## Independent owners and shared guard boundaries

| Owner/action | Recoverable behavior | Current public authority |
| --- | --- | --- |
| Deployment | Dormant/carried/Surface bodies cannot extract; actual paid rocket deployment grants orbital placement once. | `AssignSpaceMiningMission`, original `SpaceTransition` and paid construction receipt. |
| Typed queue | Missing exact destination releases only owned request/lease and waits Holding/TargetRemoved. Spent navigation deadline stays Timeout until explicit edit. Clear/edit ends action-owned partial work and preserves cargo. | `ResolveSpaceNavigationTarget`, `TickSpaceOrders`, `CancelSpaceOrders`, `CmdEditSpaceOrder`. |
| Descent | Exact paid shell/monotonic job owns whole packets; retry cannot release twice. Lost/foreign/full receiving center retains the actual descent payload, with no refund or destination substitution. Recovery expends the shell once and settles one pending claim. | `CanReleaseOrbitalCargo`, `CommitOrbitalCargoRelease`, `TickSpaceDescents`, SPOD/SPDJ. |
| Onboard service | Pending returns block service; partly used allowance is not topped up. Pausing retains countdown and materials; active native work consumes RFMT1/ELEC1 once on completion and replaces quota. | `CmdServiceLaunchProbe`, derived `IsSpaceServiceWorkTick`, `TickSpaceManifests`, SPSU. |
| Precise requested service | Explicit Core/Dock/ReturnService uses its own physical berth and original service owner. Cargo-only Recall does not create such a request. | Shared approach/berth admission and original `ExecuteSpaceOrderService` producers. |
| Generic refit | Ordinary depot refit always refuses Space. New mining resource admission requires whole actual capacity and an empty or compatible hold; no loaded packet may change meaning. | `CmdRefitVehicle`, `AssignSpaceMiningMission`, model `GetSpaceFreightCapacity`, native/same-file source validation. |
| UI | Mining Recall quotes/posts the existing native mission command; other roles retain explicit home Visit. Selected craft generation/ownership is resolved before dispatch. Mining selection submits typed commands; it cannot invent a body/hold/service route. | `SpaceSurveyWindow::OnPaint` / `OnClick` plus synchronized command admission. |
| Save and preview | Active pursuit needs a real target/deadline; attachment needs its actual lease/current body-relative point; role/work/capacity/resource and packet provenance must agree. Historical Return/Holding target is not an actionable lease. | `ValidateSpaceVehicles`, `IsSpaceMiningStateSupported`, native and copied `space_order_sl` validation. |

Ordinary center demolition remains guarded while actual dependencies exist. Forced lifecycle/company loss does not grant another center's storage or service; original Surface assets become retained unhomed custody while already orbital hulls retain their physical state. No task here introduces runtime asteroid deletion or automatic target/home selection.
